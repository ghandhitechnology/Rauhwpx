# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

All code lives under `rhwp/` — run every command below from that directory unless noted. Code comments, commit messages, and CLI output are largely in Korean; follow that convention when editing existing files.

## What this is

**rhwp** is a viewer/editor for the Korean HWP/HWPX document formats, written in Rust and compiled to WebAssembly, plus a web editor (`rhwp-studio`) with an AI agent sidebar (`rhwp-agent`) that lets a local Claude/Codex CLI read and edit the open document via MCP tools.

## Commands

### Rust core (from `rhwp/`)

- Toolchain is pinned by `rust-toolchain.toml` (1.93.1, includes `wasm32-unknown-unknown`).
- Build: `cargo build`
- All tests: `cargo test`
- Single integration test file: `cargo test --test issue_1234_some_name` (tests live in `tests/`, mostly named `issue_NNNN_*` / `pr_NNNN_*` after tracker issues; they load fixtures from `samples/`, ~430 real HWP/HWPX files)
- Single test function: `cargo test --test issue_1234_some_name test_fn_name`
- Lint/format: `cargo clippy`, `cargo fmt` (max_width 100). Clippy policy: `Cargo.toml` deliberately `allow`s many structural lints pending a phased refactor (task 142) — do not "fix" those lints in unrelated changes, and don't tighten the lint table without a dedicated tooling issue.
- WASM build (produces `pkg/`, consumed by studio): `wasm-pack build --target web` (wasm-pack 0.15.0 is the pinned version; `scripts/prepare-npm.sh` afterwards only for npm publishing)
- CLI: `cargo run --bin rhwp -- <command>` — subcommands include `info`, `export-svg|png|pdf|text|markdown|tables|hwpx|hml`, `dump`, `dump-pages`, `diag`, `search`, `convert`, `edit`, `batch`, plus many `hwp5-*` forensic probes. `capabilities --mcp` generates the MCP tool definitions; a test enforces it covers every `--json` command.
- PDF/PNG export is native-only (not wasm). `native-skia` feature enables the Skia backend. `svg2pdf` is a vendored determinism fork (`[patch.crates-io]`) — upstream is archived; keep the patch, don't migrate to krilla-svg (decision recorded in Cargo.toml).

### rhwp-studio (web editor, from `rhwp/rhwp-studio/`)

- Dev server: `npm run dev` → http://127.0.0.1:7700 (loads the engine from `../pkg/` via the `@wasm` Vite alias — build wasm first)
- Unit tests: `npm test` (Node test runner; also runs `../npm/editor/tests`)
- Type-check + build: `npm run build`
- E2E: `npm run e2e:<name>` scripts (puppeteer-core, mostly `--mode=headless`), e.g. `npm run e2e:undo`, `npm run e2e:render-diff`. Manifest check: `npm run e2e:manifest-check`.
- Rust hot-patching dev loop (Dioxus subsecond): `npm run subsecond:serve` + `npm run dev:subsecond`

### rhwp-agent (AI sidebar hub, from `rhwp/rhwp-agent/`)

- `npm start` → background WS hub on 127.0.0.1:5175 (`npm stop` to quit; `npm run start:fg` for a foreground process). Then `cd rhwp-studio && npm run dev` and use the sidebar in the browser.

### Verification tools

`tools/` holds Python harnesses used by fidelity/regression work (e.g. `verify_hwpx.py`, `roundtrip_fidelity_harness.py`, `render_page_gate.py`); `scripts/` has frontend asset/metric checks (`frontend-*.test.mjs`, `renderer_baseline.py`).

## Architecture

### Rust core (`src/`)

Pipeline: **parser → model → document_core → renderer → serializer**, exposed to JS through `wasm_api`.

- `parser/` — format readers: HWP 5.0 (CFB via `cfb`, `body_text/`, `doc_info.rs`, `record.rs`), `hwpx/` (zip+XML), `hml/`, `hwp3/`, plus `ingest/` for building documents from external input. All formats converge on the same model.
- `model/` — the in-memory document model (paragraphs, controls, tables, shapes, styles, provenance).
- `document_core/` — editing layer over the model: `commands/` (mutations), `queries/`, `builders/`, `converters/`, table calc, validation. `DocumentCore` is the main entry.
- `renderer/` — layout + rendering: line layout (`layout/`, `composer/`), `pagination/`, render tree → Canvas2D (wasm), CanvasKit, `skia/` (native), SVG (`static_svg.rs`), `pdf.rs`. Font metrics are baked in (`font_metrics_data.rs`, generated by the `font-metric-gen` bin).
- `serializer/` — writes HWPX/HML back out (roundtrip fidelity is a core project concern; many tests are roundtrip contracts).
- `wasm_api/` — the wasm-bindgen surface (`HwpDocument` etc.) consumed by studio; `typescript/rhwp.d.ts` mirrors it.
- Supporting: `wmf/`, `emf/`, `ole_chart/`, `ooxml_chart/` (embedded object formats), `diagnostics/` (CLI probes/benches), `doclang/`.

### rhwp-studio (`rhwp-studio/src/`)

TypeScript, no UI framework. `engine/` wraps the wasm module; `core/`, `view/`, `command/`, `history/` (undo), `ui/` (dialogs, command palette, `agent-sidebar/`), `hwpctl/`, `embed/`. The `agent/` directory is the studio side of the AI bridge: `bridge.ts` (WS client), `tool-executor.ts` (implements the 50 MCP tools against the engine), `pending-edits.ts` + `pending-overlay.ts` (approval queue — agent edits apply to a live preview that already shows the post-approval layout, with removed text reviewable via anchors/hover popover and sidebar cards; approve commits as a single undo step, reject restores).

### rhwp-agent (`rhwp-agent/`)

Thin local Node router — no document logic. `server.mjs` is a WS hub (`/studio`, `/mcp`, `/healthz`); `agents/claude.mjs` and `agents/codex.mjs` spawn the CLIs; each CLI spawns `mcp-stdio.mjs` as its MCP server, which forwards tool calls over WS to the hub and on to the studio tab. MCP tools are named `mcp__rhwp__<name>`: 50 tools — 17 document-read + 4 reference-read, 21 document-write (all pending approval; text/table/format edits plus find-and-replace-all, footnotes/endnotes, bookmarks, and an outline query), plus planning, download, and browser tools. **Revision contract**: every read returns a `revision`, every write requires `expectedRevision`; mismatch → `REVISION_MISMATCH`, re-read. Coordinates are body-text based `sectionIdx`/`paraIdx`/`charOffset`, 0-based.

### Other deliverables

`rhwp-chrome/`, `rhwp-firefox/`, `rhwp-safari/` (browser extensions), `rhwp-vscode/`, `rhwp-ios/`, `npm/editor` (embeddable editor package), `rhwp-shared/` (shared extension assets). `pkg/` is wasm-pack output (generated); `samples/` are test fixtures; `saved/` and `output/` hold generated artifacts.
