01

What is broken

The current path assumes the last composing input already contains the final text. Chromium and WebKit can deliver the final commit at the composition boundary or in a trailing input event.

Final event data is discarded

compositionend is bound without a CompositionEvent. The handler cannot read its final data value.

src/engine/input-handler.ts:483–484, 2642–2645
src/engine/input-handler-text.ts:414

The textarea is cleared too early

The handler switches to idle and sets textarea.value = '' during compositionend, before the browser’s trailing commit input is classified.

src/engine/input-handler-text.ts:415–430

Every preedit update mutates the document

Each IME update deletes the previous preedit from WASM, inserts the latest textarea value, moves the cursor, and schedules a canvas refresh.

src/engine/input-handler-text.ts:497–531
src/engine/input-handler.ts:2860–2880

Duplicate detection uses time and text

A 50ms window swallows input when its string matches the last composition. Event type, browser commit semantics, and session identity are absent from the decision.

03

Resolution

Move IME handling into a small deterministic session reducer. Browser adapters normalize event order; document mutation and history recording stay in one commit function.

Current path

fragile
1
Read mutable textarea value

InputEvent metadata is ignored.

2
Replace persisted text on every key

Preedit and committed content share the same WASM path.

3
Clear at compositionend

The final browser commit may still be pending.

4
Guess whether trailing input is duplicate

String equality plus a 50ms timer decides.

Target path

deterministic
1
Open one composition session

Store id, anchor, baseline text, and current preedit.

2
Normalize native events

Use event.data, inputType, and isComposing.

3
Commit final text once

Atomic replace, cursor move, one undo record, one refresh.

4
Close idempotently

Trailing commit and forced cursor moves can finish the same session once.

proposed · ime-session.ts 
idle
  → composing { id, anchor, baseline, preedit }
  → awaitingCommit { id, finalText }
  → idle

finishSession(finalText) {
  reconcile(preedit, finalText);
  commitOneHistoryEntry();
  clearNativeBufferAfterCommit();
}

05

Regression gates

The existing cursor-move E2E waits 40–200ms and explicitly omits real commit-order coverage. The new suite pins event order and fast adjacent sessions.

Reducer tests

  • Chromium order: composing input → compositionend → insertFromComposition.
  • WebKit order: commit input and compositionend in the alternate order.
  • Final data wins: last preedit differs from compositionend data.
  • Adjacent sessions: late prior input cannot mutate the next anchor.
  • Repeated text: 가가 typed within 50ms keeps both syllables.
  • Idempotence: forced finish followed by native end commits once.

Browser and editor tests

  • Fast phrase: 안녕하세요 at 0–5ms intervals produces exactly five syllables.
  • Syllable boundary: 안녕 preserves 받침 and next initial.
  • Editor surfaces: body, cell, nested cell, header/footer, and footnote.
  • Navigation: click, arrows, Enter, and blur followed by immediate Korean input.
  • History: one composition creates one undo unit and restores cursor.
  • Performance: preedit avoids full document refresh on each physical key.

Implement the session reducer and atomic final commit. This removes event-order guessing, protects adjacent Korean syllables, keeps undo coherent, and gives Chromium/WebKit differences a single adapter boundary.
