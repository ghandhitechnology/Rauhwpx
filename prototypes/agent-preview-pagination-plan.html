Engineering investigation · implemented 15 Aug 2026

Pending preview pagination repair

Make the document shown before approval use the same content and page breaks as the approved result. Review decoration stays visual; it must never add content to the paginator.

Implemented and verified Pending, approved, and rebuilt page maps now agree.

Why the preview grew—and why approval sometimes did not heal it

Two defects overlapped. The old delete_range path left deleted text in layout until approval. Separately, agent multiline insertion copied pageBreakBefore into every new paragraph; that flag lives in document IR, so approval correctly preserved the broken pagination.

1 · Pending delete Old paragraphs stay in layout markDelete(range)
2 · Pending insert New paragraphs are added too performInsert(text)
3 · Approval Old text is removed; layout rebuilds restoreSnapshot()

The invariant to enforce

For every applied-now text operation, pending and approved states contain identical document content. Approval changes review state and history ownership, not pagination.

1 · Atomic rewrite Delete and insert the real content replaceText(range, text)
2 · Review rendering Keep deleted text in metadata only oldText → overlay/popover
3 · Approval Page map remains unchanged pendingPages === approvedPages

Confirmed findings

The issue is in the agent pending-edit path, not the normal document renderer.

  • Layout received both sides of a rewrite. The legacy deletion operation was mark-only, while insertions were applied immediately.
  • Approval concealed the mismatch. approveInner() saves, restores, recomposes, and fully paginates a snapshot; that authoritative rebuild makes the page flow look normal.
  • Multiline insertion persisted a forced break on every paragraph. splitParagraph() has normal Enter semantics and inherits the source paragraph shape. Agent-inserted continuation paragraphs must clear only the inherited pageBreakBefore.
  • Incremental layout had no explicit operation boundary. Compound agent edits could expose intermediate cache state. A new IR-preserving refreshLayout() now recomposes and paginates once the logical operation is complete.
Repository status · complete delete_range is applied immediately, continuation paragraphs no longer inherit forced page breaks, and approval records an authoritative page map. HWP and HWPX browser probes both pass.

Implementation plan

Use approval’s full snapshot rebuild as a diagnostic oracle, not as the routine preview fix.

  1. Capture a deterministic failing fixture. done

    Reproduced in HWP and HWPX by inserting several paragraphs into a pageBreakBefore paragraph. Captured the page count, affected paragraph page indexes, and break metadata.

  2. Make deletion and replacement layout-real. done

    delete_range → replaceText(range, '') remains the production path. Deleted text lives in pending metadata for review UI, reject, and undo—not in the paginator.

  3. Reconcile compound mutations once. done

    The engine now rebuilds styles, composed paragraphs, measurements, page maps, and render caches from the current IR at logical agent-operation boundaries. This is not a snapshot save/restore and does not change document content.

  4. Add a pre/post-approval parity gate. done

    The browser E2E asserts equal page count and affected paragraph page indexes before approval, after approval, and after explicit authoritative refresh. Unit tests cover reject plus undo/redo.

  5. Exercise adjacent edit types. done

    The full Studio suite covers insert, delete, replace, formatting, list, object, body, and cell paths. The agent edit-loop E2E combines multiline insert, replace, paragraph/list formatting, and approval.

Acceptance criteria

  • Pending page count equals approved page count for the reproduction document.
  • Affected paragraph page indexes do not change when Approve is clicked.
  • The pending canvas shows only post-edit text; deleted text appears only in review UI.
  • Reject restores original text, paragraph structure, formatting, and pagination.
  • Approve creates exactly one undo step, and undo/redo preserve the same page map.
  • No regression for Unicode offsets, table-cell edits, typewriter reveal, or exact-diff overlays.
preview.pageMap === approved.pageMap === refreshed.pageMap === redo.pageMap

Scope and risk

  • Coordinate shift after immediate deletion Agents must use the returned collapsedAt point or prefer atomic replace_range; stale coordinates should continue to fail by revision guard.
  • Deliberate non-goals The approval UI, diff colors, and one-step undo contract are unchanged. Reconciliation rebuilds derived layout from current IR; it does not replay edits or create throwaway snapshots.
