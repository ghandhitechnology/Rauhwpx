## Implemented

- Explicit inline insertion in the core and `insertPictureEx`, with full nested-cell addresses. Legacy floating placement remains available.
- Cell images belong to the cell paragraph, reserve text-flow space, and scale down proportionally to its available width.
- Drop, clipboard and agent image insertion use the inline path. The caret retains the cell address.
- Clipboard replacement is one undo operation. Failed edits restore the document before releasing their recovery snapshot.
- Newly inserted body images trigger composition. Text insertion in nested cells reflows the affected paragraph.
- Inline picture height belongs to its actual line, not always the first line. A full-width cell picture uses its reserved object-only line instead of the following text line.
- Paragraph-relative HWPX TopAndBottom tables retain their outer margins when `flowWithText` is off, including HWP5-origin HWPX files. This fixes the measured 1 mm cell/table displacement without changing the document bytes.
- Studio initializes new `.hwpx` documents through the HWPX parser before the first edit. The bundled blank template is HWP5, and previously its live table margins changed on the first HWPX reopen. The native HWP constructor and imported HWP files retain their existing behavior.
- Session font metrics are explicit. Mac Studio HWPX documents use HCR Batang's declared Latin advances; native HWP and other environments retain the Windows reference substitution. The policy survives style rebuilds, undo, content replacement and reopening without being serialized as document content.
- Native Mac run-width measurements retain fractional advances, matching glyph positions and the WASM measurer. Independently rounding a run and its trailing space had inflated justification spacing and caused cumulative word-position drift. The Windows reference policy retains its historical rounding.
- The toolbar's all-language `fontId` change now triggers text reflow, just like `fontIds`. Previously these two ways of applying identical font properties produced different visible wrapping in body and cell paragraphs containing a picture.
- Insert, delete, split and merge maintain paragraph character counts in UTF-16 units while retaining Unicode-character selection offsets. Two supplementary characters previously shortened the live rendered text enough to hide its final period; reopening reconstructed the count and made the period reappear.
- Splitting immediately before an image retains the eight-unit control slot in the new paragraph. The split boundary now accounts for moved objects in the encoded gap before the next text character. Tests cover leading and consecutive pictures, including splits between them, and merge restoration.
- HWPX factories select font metrics before import reconstructs missing paragraph lines. Content replacement follows the same order. Normal and one-file-approved imports retain separate input limits. Existing stored line breaks are not discarded by this change.
- Regenerated HWPX packages declare at least XML version 1.4, which matches the HwpUnitChar switches the serializer emits. Controlled Mac Hancom probes show that package XML 1.2/1.3 halves these margins, while 1.4/1.5 retains the intended values. The correction preserves newer versions and unrelated producer/platform metadata. It does not halve layout values or rewrite imported content before export.
- Import now interprets HwpUnitChar paragraph margins using `version.xml@xmlVersion`. Explicit legacy versions 1.0 through 1.3 already contain doubled case values; modern packages contain effective values. Missing or unknown versions retain the existing interpretation. Default branches, flat margins, fixed line spacing, tab positions and native HWP parsing are unchanged. All six pinned version probes preserve their expected paragraph spacing across export/reopen cycles.
- Render-only correction recognizes inline cell-picture wrapping that exactly reproduces the previous Windows font metrics. It runs for HWP5-origin HWPX lineage under the HCR policy, and accepts corrected text boundaries only when every saved line's height, position, spacing, width and tag remain unchanged. Explicit breaks, position resets and altered geometry retain their stored layout. Source line data and exported bytes remain unchanged.
- A separate render-only correction recognizes doubled paragraph gaps in simple HWP5-origin HWPX body flows containing a picture with spacing before and after. Every boundary must match current or doubled paragraph properties; unexplained gaps, explicit page/column breaks, position resets, multiple columns, captions and non-inline controls are excluded. Manual line breaks remain intact because only whole-paragraph origins move. Corrected positions feed both measurement/pagination and painting. Neighbor edits recompute the whole dependent projection. Native HWP and original exported line data stay untouched.
